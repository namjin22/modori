# AI 연결(MCP)

외부 AI(Claude Code 같은 MCP 도구)가 사용자의 모도리를 읽고 바꾸는 서버 문이다. 할 일·일정은 **한 번에 여러 개**, 모든 권한 토큰이면 고치기·지우기·카테고리·루틴·프로필·설정·친구·반응까지.
모도리가 AI를 돌리는 것이 아니라, 사용자가 고른 AI가 사용자의 접근 토큰으로 들어온다(CLAUDE.md 규칙 7의 2026-11-15·2026-11-16 결정,
`docs/decisions.md` "AI 연결(MCP)", "AI 연결에 모든 권한 토큰").

## 연결하기

1. 마이페이지 > 설정 > **AI 연결**에서 접근 토큰을 만든다. 권한 셋 중 하나와 유효 기간(30·90·365일 또는 만료 없음)을 고르고, 필요하면 "친구의 공개 할 일·일정 읽기"를 켠다. 값은 만들 때 한 번만 보인다.
2. AI 도구에 서버 주소와 토큰을 넣는다. Claude Code:

   ```bash
   claude mcp add --transport http modori https://modori.site/mcp --header "Authorization: Bearer mdr_…"
   ```

   다른 도구는 "Streamable HTTP" 서버에 `Authorization: Bearer <토큰>` 머리글을 넣을 수 있어야 한다.
3. AI에게 "다음 주 시험 일정이랑 준비할 일 만들어 줘", "이번 주 안 끝낸 운동 할 일은 지워 줘"처럼 말한다.

**안 되는 것**: Claude 웹·앱의 "커넥터"처럼 로그인 창으로 연결하는 방식(OAuth 2.1)은 아직 없다.

## 권한 셋과 친구 읽기 허락

| 권한 | 할 수 있는 것 |
|---|---|
| `READ` 읽기만 | 읽기 도구 전부 |
| `WRITE` 읽기·쓰기 | 읽기 + 만들기·끝내기·옮기기·되돌리기 |
| `FULL` 모든 권한 | 쓰기 + 고치기·지우기, 카테고리·루틴, 프로필·설정, 친구·반응 |

`FULL`을 따로 둔 까닭: 11월 15일에 만든 `WRITE` 토큰은 "지우거나 고칠 수 없다"는 약속으로 만들어졌다. 그 뜻이 몰래 넓어지지 않게 새 단계를 둔다.
**친구의 공개 할 일·일정 읽기**(`ApiToken.allowFriends`)는 권한과 별개로 토큰마다 켠다(기본 꺼짐). 읽기만 토큰에도 켤 수 있고, 모든 권한 토큰이어도 안 켜면 친구 정보는 안 나간다.
토큰이 허락하지 않은 도구는 `tools/list`에 나오지 않고, 불러도 "없는 도구"다.

| `list_todos` | 기간(최대 62일, 300개)의 할 일. `includeMemo`를 켜야 메모가 나간다 |
| `list_events` | 기간에 걸친 일정(반복 일정은 `list_routines`) |
| `list_routines` | 루틴(할 일 루틴)과 반복 일정, 반복 규칙·멈춤 여부 |
| `get_profile` | 닉네임·소개·언어·시간대·알림 설정·팔로우 수 |
| `search_users` | 닉네임 일부로 사람 찾기(최대 20, 차단 관계는 안 나온다), 내가 팔로우 중인지. 닉네임만 나간다(친구 찾기 화면과 같다) |
| `list_people` | 내가 팔로우하는 사람 / 나를 팔로우하는 사람 |

| 도구 | 하는 일 |
|---|---|
| `list_friend_todos` | 친구가 팔로워에게 보여 주는 할 일(공개 카테고리만, 메모는 친구가 공개로 켠 것만) |
| `list_friend_events` | 친구가 보여 주는 일정(반복 일정은 날짜로 펼쳐서) |

| 도구 | 하는 일 |
|---|---|
| `create_todos` | 할 일 최대 20개. 카테고리는 id나 이름. 메모(500자)도 같이 적을 수 있다. 전부 되거나 하나도 안 된다. `batchId` |
| `add_todo_memos` | 이미 있는 할 일 최대 20개에 메모를 단다. 기본은 있던 메모 뒤에 줄을 바꿔 덧붙이고(`replace: true`면 바꿈), 합쳐 500자를 넘으면 거절한다. AI가 쓴 메모는 팔로워에게 안 보인다(`memoPublic=false`). 글·카테고리는 건드리지 않는다. `batchId` |
| `complete_todos` | id 최대 50개를 끝냄/안 끝냄으로 |
| `move_todos` | id 최대 50개를 다른 날로(루틴이 만든 할 일은 그날 루틴이 다시 안 생기게 건너뛴 날로 남긴다) |
| `create_events` | 일정 최대 10개. 기본 **비공개**, 메모는 늘 비공개. `batchId` |
| `undo_batch` | `batchId`로 그 요청이 한 일을 24시간 안에 되돌린다(아래) |

모든 권한(`FULL`):

| 도구 | 하는 일 |
|---|---|
| `update_todos` | 할 일 최대 20개의 글·메모·메모 공개·카테고리. 전부 아니면 무. `batchId`(고치기 전 값 보관) |
| `delete_todos` | 할 일 최대 50개 지우기. 루틴이 만든 것은 그 날을 건너뛴다고 남긴다. `batchId` |
| `update_events` | 일정 최대 10개의 이름·날짜·시각·색·메모·공개·D-day. `batchId` |
| `delete_events` | 일정 최대 10개 지우기. `batchId` |
| `create_category` / `update_category` / `delete_category` | 카테고리(전체 10개까지). 기본 **비공개**. 지우면 할 일은 "카테고리 없음"으로 남고 루틴은 멈춘다. 만들기·고치기는 되돌릴 값(`previous`)을 돌려주고, 지우기는 `batchId` |
| `create_routine` / `update_routine` / `delete_routine` | 할 일 루틴(`kind: todo`, 카테고리 필수)과 반복 일정(`kind: event`, 기본 비공개). 둘을 합쳐 50개까지. 주기 DAILY·WEEKLY(요일 0~6)·MONTHLY(날짜 1~31). 멈춤·다시 돌림은 `update_routine`의 `paused`. 지우기는 `batchId` |
| `update_profile` | 닉네임(유일·20자)·소개(100자)·캐릭터. 사진은 못 올린다. `previous` |
| `update_settings` | 시간대, 친구가 끝내면 푸시, 추천 친구에 안 나오기, 오늘 일정 알림 시각(5분 단위, null이면 끔). `previous`. **언어는 못 바꾼다** |
| `follow_user` / `unfollow_user` / `remove_follower` | 닉네임으로 팔로우·끊기·내 팔로워 끊기. 팔로우하면 상대가 푸시를 받는다 |
| `set_reaction` | 팔로우한 사람의 **끝낸 공개 카테고리 할 일**에 이모지 반응 보내기, `on=false`로 내 반응 지우기. 상대가 푸시를 받는다 |

**일부러 없는 것**: 토큰 만들기·지우기(토큰이 토큰을 만들면 권한 상승이다), 계정 지우기, 로그인 방법·연결 계정, 프로필 사진 올리기(이미지), "내가 정한 알림"(알림 문구를 AI가 정하는 것은 `CLAUDE.md` 규칙 7이 허용한 범위 밖이다), 차단·신고(안전 장치는 사람이 쓴다),
언어 바꾸기(이 기기의 쿠키가 계정 값을 덮어써서 약속할 수 없다).

## 되돌리기(`undo_batch`)

고치거나 지우는 요청은 **바꾸기 전의 모습**(`McpBatch.snapshot`, `lib/mcp/snapshot.ts`)을 남기고 `batchId`를 돌려준다. `undo_batch`가 24시간 안에 그 모습으로 되돌린다(`lib/mcp/undo.ts`).

- 만들기: 만든 것을 지운다(그새 사용자가 끝낸 할 일은 남긴다).
- 할 일·일정 고치기, 메모 달기: 글·메모·메모 공개 여부·카테고리·기간 등을 고치기 전 값으로.
- 할 일·일정·카테고리·루틴·반복 일정 지우기: 같은 id로 다시 만든다. 카테고리·루틴은 아직 본인 것으로 있을 때만 다시 잇고, 새로 만드는 것과 같은 상한(하루 50개, 일정 5개, 카테고리 10개…)을 지킨다. 못 되돌린 것은 이유와 함께 `skipped`로 알린다.
- **되돌려지지 않는 것**: 지운 할 일에 친구가 보낸 반응(지울 때 같이 사라진다), 카테고리·루틴·프로필·설정을 고친 것(고치기 전 값 `previous`로 다시 고치면 된다), 팔로우·반응(반대 도구로).
- 한 번 쓴 묶음은 지운다. 7일 넘은 묶음 기록은 다음에 AI가 바꿀 때 지운다.

## 지키는 규칙

서버 액션(`app/(tabs)/actions.ts`, `events/actions.ts`, `categories/actions.ts`, `routines/actions.ts`, `routines/event-routine-actions.ts`, `feed/actions.ts`, `settings/actions.ts`, `settings/profile/actions.ts`)과 같다.
**`lib/mcp/*-tools.ts`에 다시 적은 것이라, 규칙을 바꿀 때 두 곳을 같이 고친다.**

- 할 일 하루 50개, 일정 하루 5개(여러 날 일정은 날마다 센다)·전체 1000개, 카테고리 10개, 루틴 50개(할 일 루틴+반복 일정), 할 일 날짜는 오늘에서 ±3650일(10년, 2026-11-17에 366일에서 넓힘), 일정 길이 366일 이하
- 일정 시각: 끝 시각은 시작 시각이 있어야 하고, 같은 날이면 시작보다 빠를 수 없다. 시작 시각을 지우면 끝 시각도 지워진다
- 반복 규칙: 주간은 요일이, 월간은 날짜가 하나는 있어야 한다. 끝 날짜는 시작보다 이르지 않게(`lib/mcp/routine-rule.ts`)
- 반응: 팔로우한 사람의, 끝낸, 공개 카테고리 할 일에만(`toggleReaction`과 같다). 같은 할 일에 첫 반응일 때만 10분에 한 번 푸시
- 친구 읽기: 팔로우한 사람만, 차단 관계는 "없는 사람". 공개 카테고리의 할 일·`isPublic` 일정·`memoPublic` 메모만
- 카테고리·루틴·일정·메모는 본인 것이고, 모든 질의에 `userId`를 건다(남의 id는 "없음"으로 답한다)
- AI가 만든 메모·카테고리·일정·반복 일정은 기본 비공개(`memoPublic=false`, `isPublic=false`)
- 친구에게 가는 "끝냈어요" 알림은 한 번에 5개까지(`after()`로 응답 뒤에)

## 인증과 한도

- `lib/mcp/auth.ts`: `Authorization: Bearer mdr_…`(`mdr_` + 43자)만 본다. 쿠키·세션은 보지 않는다. 모양이 틀리면 DB를 부르지 않고 401. 없는·지운·만료된 토큰은 모두 같은 401.
- 토큰 값은 저장하지 않고 SHA-256 해시(`ApiToken.tokenHash`)만 둔다. 마지막 사용 시각은 10분에 한 번만 적는다.
- 속도: 토큰마다 요청 60개 버스트 + 초당 1개. 바꾸는 도구는 별도로 10개 버스트 + 6초에 1개. **남에게 닿는 일(팔로우·끊기·반응)은 거기에 5개 버스트 + 15초에 1개를 더 건다**(검증에서 막힌 요청도 센다). 요청 본문은 64KB까지.
- `GET`·`DELETE /mcp`는 405(세션·SSE를 쓰지 않는다).
- 가입(닉네임)을 끝내지 않은 계정의 토큰은 403.

## 위험과 한계

- **프롬프트 주입**: AI가 다른 곳에서 읽은 글에 속아 쓰기·모든 권한 도구를 부를 수 있다. 개수·속도 상한, 되돌리기, 만들 때 비공개 기본값, 읽기 전용 토큰(기본 선택)으로 줄였다. **모든 권한 토큰은 그 위험이 가장 크다**: 속은 AI가 할 일을 지우고, 친구를 팔로우하고, 반응을 보내고, 프로필을 바꿀 수 있다. 되돌리기는 24시간 안, 지운 할 일에 달린 반응은 못 되살린다.
- 토큰이 새면 그 사람의 할 일·일정이 읽히고, 모든 권한이면 위의 일이 모두 된다. 마이페이지에서 지우면 바로 막힌다.
- **친구 정보 읽기**: 친구가 정한 공개 범위는 "모도리 안의 팔로워에게 보이기"였지 "그 팔로워가 고른 AI 서비스로 보내기"가 아니다. 그래서 토큰마다 따로 켜게 했지만, 친구에게는 알리지 않는다. 켠 순간부터 그 내용은 그 AI 서비스의 약관을 따른다(방침에 적었다).
- 남에게 닿는 일(팔로우·반응)은 사용자 이름으로 가므로, 잘못 보내면 되돌릴 수 없는 인상이 남는다(푸시는 한 번 가면 회수할 수 없다). 그래서 따로 좁게 센다.
- 실제 클라이언트(Claude Code 등)로의 연결은 배포 뒤 사람이 한 번 확인해야 한다.
