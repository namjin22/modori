# 릴리스 스크린샷

화면이 어떻게 바뀌어 왔는지 남긴다. 지난 화면은 코드를 되돌려도 같은 데이터로 다시 찍기 어렵다.

## 언제 찍나

- **화면이 눈에 띄게 바뀐 PR을 main에 머지하고, 배포가 끝난 것을 확인한 뒤** 같은 날 찍는다.
- 하루에 여러 번 배포했으면 그날 마지막 배포 뒤 한 번만 찍는다(같은 날 폴더를 덮어쓴다).
- 문서·서버 내부·테스트만 바뀐 배포는 찍지 않는다.
- 찍었으면 아래 "릴리스 목록"에 한 줄 더한다.

## 어떻게 찍나

```bash
npm run screenshots                          # docs/screenshots/<오늘 날짜>/
SCREENSHOT_DIR=2026-10-01 npm run screenshots  # 폴더 이름을 정할 때
```

- `tests/screenshots/capture.spec.ts`가 테스트 DB에 데모 계정 둘("모도리", "도리친구")과 할 일·일정·반응을 만들고,
  E2E와 같은 서버(프로덕션 빌드)에서 찍은 뒤 계정을 지운다. 3101 포트를 쓰므로 E2E와 동시에 돌리지 않는다.
- **운영 사이트는 찍지 않는다.** 실제 사용자의 닉네임·할 일이 공개 저장소에 올라간다.
- 데모 데이터가 늘 같아서 릴리스끼리 나란히 비교할 수 있다. 날짜만 찍는 날을 따른다.
- JPEG(품질 80), 페이지 전체 높이. 한 번에 25장, 약 0.8MB.

## 무엇을 찍나

폰(390×844)과 데스크톱(1440×900), 라이트 테마. 다크는 홈만.

| 번호 | 화면 | 주소 |
|---|---|---|
| 01 | 로그인 | `/login` |
| 02 | 홈(내 하루, 달력) | `/` |
| 03 | 달력 펼침(폰만) | `/?view=month` |
| 04 | 소셜 피드 | `/feed` |
| 05 | 친구 화면 | `/feed/u/<친구>` |
| 06 | 알림 | `/feed/reactions` |
| 07 | 기록 | `/stats` |
| 08 | 마이페이지 | `/settings` |
| 09 | 홈 다크 | `/` |
| 10 | 할 일 창(메모, 다른 날에 하기) | `/`에서 할 일을 누름 |

화면이 새로 생기면 뒤 번호를 붙여 더한다. 예전 번호는 바꾸지 않는다(폴더끼리 같은 번호가 같은 화면이어야 한다).
