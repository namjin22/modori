# 플랫폼별 기능 분담

웹(modori.site), 데스크톱 앱(`desktop/`, Electron), 모바일 앱(Capacitor로 웹을 감싼 앱 `mobile/`. Android는 Google Play 비공개 테스트에 올리는 중, iOS는 TestFlight 준비 중)이
무엇을 나눠 맡는지 정한다. 2026-09-29 초안, 2026-10-03 모바일 현황 갱신.

## 원칙

- **기능은 웹에 한 번만 만든다.** 데스크톱·모바일 앱은 웹을 띄우는 껍데기라, 할 일·소셜 기능은 어디서나 똑같다.
  앱마다 따로 만들면 세 벌을 고쳐야 하고 어긋난다.
- 앱은 **그 플랫폼에서만 되는 것**(창, 로그인 넘겨받기, 푸시, 설치)만 맡는다.
- 제외 기능(CLAUDE.md 규칙 7)은 어느 플랫폼에도 넣지 않는다. 푸시는 친구가 보낸 반응·새 팔로워, 켠 사람에게 하루 한 번 보내는 할 일 리마인드(2026-10-14), 내가 정한 시각·요일·문구의 알림(2026-10-26)에만 쓴다.

## 정하지 않은 것

- 컴퓨터 알림: 브라우저는 웹 푸시(창을 닫아도 온다), 데스크톱 앱은 창이 열려 있는 동안만(1분마다 확인). 웹 푸시를 못 켜는 브라우저도 창이 열려 있을 때로 남는다(2026-10-19, `docs/decisions.md`).
  데스크톱에서도 원하는 사람이 많으면 다시 본다.
- 홈 화면 위젯: 스토어 앱이 나간 뒤에 본다. iOS(Swift)·Android(Kotlin)를 따로 만들어야 하는 큰 작업이다.
- 모바일 스토어 출시 방식: Capacitor로 웹을 감싸는 쪽을 권한다(데스크톱과 같은 구조). 새 의존성이라 사용자 승인을 받은 뒤 시작하고 결정 기록에 남긴다.
- 맥 데스크톱 앱: 나중에(2026-09-29 사용자). 지금 dmg는 M1 이상 전용이고 서명이 없다. 맥북을 빌릴 수 있어 서명·공증까지 해 볼 수 있다.
  그전에는 브라우저의 "앱으로 설치"(크롬·엣지 설치 아이콘, 사파리 Dock에 추가)가 가장 무난하다.
