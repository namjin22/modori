# 장애·버그 기록

운영(또는 운영 배포)에 영향이 있었거나, 배포 시험에서 잡혀 운영에 나갈 뻔한 문제를 적는다.
테스트에서만 드러나 바로 고친 버그는 `docs/handoff.md`에 둔다.

같은 일이 다시 났을 때 "지난번엔 어떻게 했지"에 답하고, 재발 방지가 실제로 들어갔는지 확인하려고 남긴다.
증상을 겪는 동안 바로 적기 시작하고(시각이 가장 먼저 사라진다), 고친 뒤 나머지를 채운다.

## 양식

```markdown
### INC-<번호> <한 줄 요약> (<발생 날짜>)

- **영향**: 누가, 얼마나, 얼마 동안 (예: 운영 전체 / DataGSM 로그인 사용자 / 영향 없음 — 배포 시험에서 발견)
- **발견**: 어떻게 알았나 (사용자 제보, health 알림, errors 알림, 배포 실패, 직접 발견)
- **증상**: 사용자나 운영자가 본 것. 오류 원문이 있으면 그대로(토큰·쿠키·개인정보는 지운다)
- **원인**: 왜 그랬나. 추측이면 추측이라고 쓴다
- **조치**: 무엇을 했나. 커밋·PR 번호
- **재발 방지**: 다시 안 나게(또는 나면 바로 알게) 무엇을 바꿨나. 테스트·알림·규칙·문서. 없으면 "없음"과 이유
```

- 번호는 이어서 붙이고 지우지 않는다.
- 사용자의 이름·이메일·할 일 내용은 적지 않는다. 저장소가 공개다.
- "재발 방지"가 "조심한다"뿐이면 아직 안 끝난 것이다. 테스트나 알림처럼 사람이 잊어도 도는 것을 적는다.

## 기록

### INC-5 알림을 봐도 아래 소셜 탭의 알림 수가 사라지지 않는다 (2026-09-29 제보)

- **영향**: 알림을 받은 모든 사용자. 알림 수 뱃지가 도입된 뒤부터 2026-09-29 수정 배포까지. 새로고침하면 사라졌다
- **발견**: 운영자 제보
- **증상**: 소셜 → 알림을 열어 NEW를 확인하고 링크로 돌아와도 아래 탭의 숫자가 그대로 남았다
- **원인**: 알림 수는 탭 공통 레이아웃(`app/(tabs)/layout.tsx`)이 센다. Next App Router는 링크로 오갈 때 공통 레이아웃을
  다시 그리지 않아, 알림 화면이 읽은 시각을 갱신해도 레이아웃의 숫자는 처음 그린 값으로 남았다. 처음 불러올 때도 레이아웃이
  화면보다 먼저 숫자를 세서 같은 요청 안에서 갱신 전 값이 나왔다. 기존 E2E는 매번 `page.goto`로 새로 불러와 이 경로를 밟지 않았다
- **조치**: 알림 화면이 뜬 뒤 서버 액션(`markNotificationsSeen`)이 `revalidatePath("/", "layout")`로 레이아웃을 다시 그리게 했다.
  읽은 시각은 여전히 화면을 그릴 때 남긴다(바로 떠나도 읽은 것으로). 보는 동안 NEW가 사라지지 않게 처음 값을 붙잡았다
- **재발 방지**: 링크로만 오가며 뱃지가 사라지는지 보는 E2E(`tests/e2e/notification-badge.spec.ts`). 고치기 전 코드에서 실패하는 것을 먼저 확인했다

### INC-4 배포 스크립트가 DB가 켜지기 전에 마이그레이션을 돌리고, 고장 난 버전을 그대로 둔다 (2026-09-27)

- **영향**: 없음 — 운영에 나가기 전 배포 시험(포트·이미지를 운영과 분리)에서 발견
- **발견**: 직접 발견. 새 VM으로 복구하는 경우와 켜자마자 죽는 이미지를 흉내 내 시험했다
- **증상**: DB 컨테이너가 막 켜진 직후에는 마이그레이션이 실패해 첫 배포가 멈췄다. 새 버전이 응답하지 않아도
  배포는 실패로만 끝나고 고장 난 버전이 떠 있었다
- **원인**: 배포 스크립트가 DB 준비를 기다리지 않았고, 새 버전이 뜨는지 확인한 뒤 되돌리는 단계가 없었다
- **조치**: `docker compose up -d --wait db`로 DB 준비를 기다리고, 직전 이미지를 `modori:previous`로 남겨 60초 안에
  응답이 없으면 되돌린다(2026-09-27 커밋 "fix: 배포가 DB 준비를 기다리고, 새 버전이 뜨지 않으면 직전 버전으로 되돌린다")
- **재발 방지**: 되돌림 시험 방법을 `deploy/README.md`에 두고 출시 체크리스트 P0에 "배포 실패 시 직전 버전으로 되돌린다(시험 완료)"

### INC-3 운영에서 DataGSM 로그인이 되지 않는다 (2026-09-20)

- **영향**: DataGSM으로 로그인하려는 모든 사용자(Google 로그인은 정상). 2026-09-20 연결 배포부터 2026-09-21 수정 배포까지
- **발견**: 운영에서 DataGSM 로그인을 시도해 확인(사용자)
- **증상**: DataGSM 화면에서 아이디·비밀번호를 넣으면 `/api/auth/error?error=Configuration`(영어 "Server error" 화면)으로
  돌아왔다. Vercel 로그에는 콜백에서 `error: invalid_request`, 밖으로 나간 요청 없음(userinfo까지 가지 못함)
- **원인**: 두 가지였다(2026-09-21 요청을 직접 보내 측정). ① `checks: ["pkce"]`만 둬서 authorize 요청에 state가
  빠졌다. ② 토큰 요청을 JSON으로 바꾸는 코드가 Authorization 헤더를 지우는데 본문에도 자격 증명이 없어 어떤 인증도
  실리지 않았다. 토큰 엔드포인트는 JSON 본문 + 본문 자격 증명만 받는다(Basic 헤더 401, form 본문 415)
- **조치**: `checks: ["state", "pkce"]`, `client_secret_post`(2026-09-21 커밋 "fix: DataGSM 로그인의 state와 토큰 요청
  형식을 바로잡는다"). 배포 뒤 실제 로그인 성공 확인
- **재발 방지**: `lib/auth.ts`의 DataGSM 설정마다 왜 필요한지 주석을 달았다. 로그인 오류는 제공자 오류 코드를 남긴다
  (`logger.error`, 인가 코드는 버림). 실제 OAuth는 E2E로 시험할 수 없어 자동 검사는 없다

### INC-2 글꼴(Pretendard)이 운영에서 전혀 불러와지지 않는다 (2026-09-16)

- **영향**: 모든 사용자, 모든 화면이 시스템 글꼴로 보였다. 첫 배포부터 2026-09-16 수정까지
- **발견**: 빌드 경고
- **증상**: 화면 글꼴이 디자인과 달랐다. 오류는 없었다
- **원인**: `globals.css`의 `@import url(...)`가 Tailwind가 앞에 붙인 규칙 뒤로 밀렸다. 브라우저는 규칙 뒤의
  `@import`를 무시한다
- **조치**: `app/layout.tsx`의 `<link rel="stylesheet">`로 옮겼다(86e631e)
- **재발 방지**: 없음 — 빌드 경고를 읽는 것에 기댄다. 글꼴을 확인하는 테스트는 두지 않았다

### INC-1 Vercel 배포가 `prisma generate`에서 실패한다 (2026-09-16)

- **영향**: 배포가 막혔다(운영 중이던 버전은 그대로)
- **발견**: 배포 실패
- **증상**: `postinstall`의 `prisma generate`가 `CLI.UNKNOWN_COMMAND`로 실패
- **원인**: 버전을 정하지 않고 설치해 npm `latest` 태그의 `prisma@8.0.0-rc.15`가 깔렸고, `@prisma/client`는 7.10.0이라
  CLI와 client의 메이저 버전이 어긋났다. 8 RC CLI는 명령 체계가 다르다
- **조치**: CLI와 client를 둘 다 `6.19.3`으로 정확히 고정(b957ebb). 결정은 `docs/decisions.md` "Prisma는 6.x로 고정한다"
- **재발 방지**: CLAUDE.md "버전 주의"에 Prisma 6.x 고정 규칙, `package-lock.json`을 같이 커밋(배포는 `npm ci`)
