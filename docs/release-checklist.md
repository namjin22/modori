# 출시 전 체크리스트

실제 사용자를 초대하기 전에 확인할 항목이다. P0이 하나라도 비어 있으면 공개하지 않는다.
2026-09-28에 GSMSV 운영 기준으로 새로 썼다(예전 판은 Vercel 기준이었다).

## P0: 출시 차단

- [x] `npm run verify` 전체 통과 (단위 77×3 + 3, E2E 전체)
- [x] 운영 주소 `https://modori.site` — HTTPS, http→https 308, 보안 헤더 5개
- [x] Google·DataGSM 로그인이 운영에서 된다 (사용자가 직접 로그인 확인)
- [x] 운영에 우회 로그인(mock)이 없다 — `/api/auth/providers`에 google·datagsm만, mock 콜백은 Configuration 오류로 거절
- [x] 운영 DB 마이그레이션이 최신이다 — 배포 스크립트가 `prisma migrate deploy`를 돌리고, 최근 배포 로그에서 확인
- [x] 계정 삭제가 할 일·카테고리·루틴·일정·팔로우(양쪽)·반응(주고받은)·계정·세션을 모두 지운다 (account.spec)
- [x] 개인정보처리방침 `/privacy`, 가입할 때 필수 동의와 동의 시각 저장
- [x] 백업: 매일 04:00 VM 안 7일치 + 백업용 Neon. 백업용 Neon만으로 복원 훈련 성공(표 9개 행 수 일치, 앱 기동)
- [x] 배포가 실패하면 직전 버전으로 되돌린다(시험 완료)
- [ ] 실제 아이폰(사파리)·안드로이드(크롬)에서 로그인, 할 일 추가·체크·수정·삭제, 손가락으로 끌어 순서 바꾸기, 홈 화면에 추가
- [ ] 운영자(이남진)가 방침 내용을 읽고 확인 — 법률 검토를 거친 문서는 아니다

## P1: 출시 직후

- [x] 서버 상태 감시 — GitHub Actions `health`. **실제 간격이 2.5~6시간**(GitHub 예약 실행이 밀린다)이라 서버가 죽어도
  몇 시간 모를 수 있다. 더 촘촘히: UptimeRobot 등록(사용자 가입 필요, 5분 간격 무료) [ ]
- [x] 오류 모니터링 — 서버·브라우저 오류를 DB에 기록, `/admin/errors`(운영자만), `errors` 워크플로가 매시간 수만 확인해 알림
- [x] 요청 속도 제한 — 세션마다 60/초당 6, 로그인 전 IP마다 300/초당 30(학교 와이파이 공인 IP 공유 고려)
- [x] 개수 상한 — 할 일 하루 50, 카테고리 10, 루틴 50, 일정 1000
- [x] 의견 보내기 — 마이페이지, 운영자 메일로
- [ ] DataGSM API 키 만료일 확인 — 만료되면 DataGSM 로그인이 전부 막힌다. DataGSM 개발자 화면에서 날짜를 보고
  여기 적어 두고, 만료 30일 전에 갱신(사용자)
- [ ] 동의 기능(9/28 02:47 배포) 전에 가입을 마친 계정 **3개**는 동의 기록이 비어 있다(9/28 운영 DB 확인. 닉네임을 안 정한 1개는
  가입을 마칠 때 동의한다) — 다시 동의받을지 결정(사용자)
- [ ] 백업용 Neon 비밀번호 교체(채팅에 노출됨)
