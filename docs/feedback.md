# 사용자 요청 기록

받은 요청과 그 결과를 적는다. **안 한 것은 왜 안 했는지를 반드시 적는다.** 몇 달 뒤 "그때 왜 이걸 안 했지"에
답할 수 있는 것은 이 칸뿐이다. 이유 없이 "안 함"이나 "나중에"만 적지 않는다.

## 적는 법

| 칸 | 적는 것 |
|---|---|
| 날짜 | 요청을 받은 날(YYYY-MM-DD) |
| 누가 | 역할만: 운영자 / 베타 사용자 / 사용자(메일) / 사용자(대화) 등. **이름·이메일은 적지 않는다**(저장소가 공개다) |
| 요청 | 요청한 말에 가깝게 한 줄. 해석이 들어가면 "(해석: …)" |
| 결과 | 반영 / 일부 반영 / 다르게 반영 / 안 함 / 보류 |
| 안 한 이유 | 반영이 아니면 **필수**. 무엇을 안 했고 왜인지. 규칙(CLAUDE.md), 개인정보, 비용, 다른 요청과 충돌, 우선순위(무엇보다 뒤인지)처럼 구체적으로. 보류면 무엇이 정해져야 하는지와 누가 정하는지 |
| 관련 | PR 번호, `docs/decisions.md` 항목, 커밋 |

- 새 요청은 표 맨 아래에 더한다. 결과가 바뀌면 그 줄을 고치고 날짜를 이유 칸에 적는다(예: "10/3 반영").
- 운영자가 사용자에게 들은 것을 전해 준 요청은 "베타 사용자(운영자 전달)"로 적는다.
- 2026-09-28 이전 요청은 `docs/backlog.md`와 `docs/handoff.md`에 흩어져 있다. 옮겨 적지 않았다.
